# AGENT.md

Context for AI coding agents working in this repo. See [README.md](README.md) for the full human-facing guide.

## What this is

A Docusaurus 3 (TypeScript, React 19) documentation site for "Wealth Intelligence," deployed to GitHub Pages. No blog, no built-in `docs` plugin instance — instead four independent `@docusaurus/plugin-content-docs` instances, one per top-level section.

## Commands

```bash
npm install       # install deps (Node >= 20 required)
npm start         # dev server at /technical-product-website-template/, hot-reloads .mdx/.tsx
npm run build     # production build -> build/
npm run serve     # preview production build
npm run typecheck # tsc, no emit
npm run clear     # clear Docusaurus cache (.docusaurus/) if things get weird
```

There is no lint/test script configured. `npm run typecheck` is the only automated check — run it after editing `.ts`/`.tsx` files.

Deploy (`GIT_USER=<user> npm run deploy`) force-pushes `build/` to `gh-pages`. This is a real, hard-to-reverse publish action — never run it without the user explicitly asking.

## Structure

- `docs-product-overview/`, `docs-architecture-design/`, `docs-market-deployment/`, `docs-community-resources/` — the four content sections. Each is its own plugin instance with its own `routeBasePath` and sidebar file.
- `sidebars<Section>.ts` — one per section, currently all `{type: 'autogenerated', dirName: '.'}`. Adding a page under an existing directory needs no sidebar edit; ordering is controlled via `sidebar_position` frontmatter in each `.mdx` file.
- `src/pages/` — standalone React pages (currently just the homepage `index.tsx`).
- `src/components/` — `HomepageFeatures` (feature grid) and `HeroTriangles` (homepage hero graphic).
- `src/css/custom.css` — global CSS/theme overrides (Infima variables).
- `static/img/` — logo, favicon, social card, and all doc-page images/diagrams. `docs/undraw_*.svg` placeholders were removed as part of the rebrand — don't reintroduce them.
- `docusaurus.config.ts` — single source of truth for title, nav, footer, GitHub Pages URL/org/project, and the four plugin-content-docs entries.

## Conventions

- New docs page: add an `.mdx` file with frontmatter (`sidebar_position: N`) inside the correct `docs-*/` directory — sidebars are autogenerated, no manual registration needed.
- New page *group* (collapsible sidebar folder): subfolder + `_category_.json` (`label`, `position`, optional `link`) + `index.mdx`. See README's "Add a new page group" for the full example.
- New top-level *section*: duplicate a `plugin-content-docs` block in `docusaurus.config.ts` (new `id`/`path`/`routeBasePath`/`sidebarPath`), add a matching `sidebars<Section>.ts`, and add a `docSidebar` navbar item.
- Site branding (title "Wealth Intelligence", tagline, GitHub org `twinzom`, repo `technical-product-website-template`) lives entirely in `docusaurus.config.ts` — change it there, not by hardcoding strings elsewhere.
- `onBrokenLinks: 'throw'` — a broken internal link fails the build, not just a warning. Always run `npm run build` after restructuring/renaming docs to catch this.
- Diagrams default to `.drawio.svg` — a plain SVG with the editable draw.io/diagrams.net graph model embedded in its `content` attribute, so it renders everywhere as a normal image but can still be opened and edited in draw.io.
- All doc images/diagrams live under `static/img/`, mirrored to match the referencing doc's path: a page in `docs-product-overview/` uses `static/img/product-overview/...`, a page in `docs-architecture-design/Natural-Language-Querying/` uses `static/img/architecture-design/Natural-Language-Querying/...` (drop the `docs-` prefix from the section folder, keep any subfolder). Reference them from `.mdx` with a root-relative path, e.g. `![alt](/img/product-overview/diagram-name.drawio.svg)` — Docusaurus rewrites this to include `baseUrl` automatically.
